## 2. Application — libxml2 (R8, Step 4) and the ABI stop (Step 6)

**Source.** NVD CVE API; GNOME release index and `.sha256sum` files; release `NEWS`.

| Advisory | NVD affected range | First fixed upstream |
|---|---|---|
| **CVE-2026-6653 (Critical)** | 2.9.11 ≤ v ≤ 2.11.0 | any release > 2.11.0 (e.g. 2.13.9) |
| CVE-2026-86138, -86139, -86140, -86142, -86143, -86144 (High) | v < 2.15.4 | **2.15.4 only** (NEWS: dict.c/uri.c/valid.c overflow checks, xpointer, xmlIO write callback, xinclude parseFlags) |
| CVE-2026-74860 (High) | Python bindings only | not built in any candidate |
| (also) CVE-2026-0989/-0990/-0992 (Low/Medium) | v < 2.15.2 | 2.15.2 |

Upstream lines and their ABI:

| Line | Soname | Last release | Fixes the Critical | Fixes the Highs |
|---|---|---|---|---|
| 2.13.9 | **`libxml2.so.2`** (ABI-compatible with PHP) | Sep 2025 (**unmaintained**) | yes | **no** |
| 2.14.6 | `libxml2.so.16` | Sep 2025 | yes | no |
| 2.15.4 | **`libxml2.so.16`** (`so_version = 2 + 14`) | Sep 2026 (maintained) | yes | **yes** |

The official PHP 8.3.35 binary links `libxml2.so.2`. The only upstream
release that fixes the Critical **and** the six libxml2 Highs is 2.15.4, a
new soname. Using it means building PHP 8.3.35 from source against it,
leaving the official PHP binary. That is exactly the ABI-breaking change
Step 6 says to stop and report before forcing. **Stopped; no application
change was made in this unit.**

2.15.4 source integrity (R9): tarball sha256
`98087fd181d9070724f3fbc65c7377db03038eb92bd882374daff44940138821`, matching
GNOME's published `.sha256sum`. GNOME publishes no detached signature.

### Decision required (owner/security)

1. **Rebuild PHP 8.3.35 from the official PHP source**, pinned and verified,
   using the official image family's own `docker-php-source`/build recipe on
   the same Debian 13 base, against libxml2 2.15.4 and curl 8.22.0 built in
   digest-pinned stages. This clears every libcurl and libxml2 Critical and
   High. The runtime would ship our PHP build instead of the official
   binary: an architectural change with ongoing rebuild duty for every PHP
   patch release.
2. **Keep the official PHP binary** with curl 8.22.0 and libxml2 2.13.9
   (`.so.2`). This clears the Critical, but six libxml2 Highs stay fixed only
   in an ABI-breaking release. You would have to rule whether "fix requires
   an ABI break" counts as a High-with-fix (R16: must fix, i.e. option 1) or
   no-fix (exception path). It also swaps Debian's maintained 2.9.14 security
   backports for an unmaintained upstream line that lacks the 2.15.x fixes
   (e.g. CVE-2026-0989/0990/0992). **Not recommended.**
3. Wait for Debian 13 fixes. This contradicts R8.

**Recommendation:** option 1. It is the only option that removes the
vulnerable code rather than relabelling it. It also avoids the stale Debian
package metadata problem of R11 entirely: the Debian `libcurl4t64`/`libxml2`
packages would no longer be needed by PHP and could be removed normally,
while the source-built libraries stay pinned and verified.

## 3. AI Gateway — Python 3.14 (R12–R14)

**Base:** `python:3.12.14-slim-trixie@sha256:f77ac9e4…` →
**`python:3.14.7-slim-trixie@sha256:51dafde81dbdb6ebde285137a295cf18a47ca95234fe388a343719cb97305b3d`**
(CPython 3.12.14 → 3.14.7; Debian 13; the same official slim family). The

- **Wheels (R14):** every locked package has a cp314 (or abi3/pure) wheel.

- **Image:** `verify-images.sh` 68/68, including the new "gateway runs

- **Scan:** **0 CRITICAL, 0 HIGH with a fix, 49 HIGH without a fix** (12
